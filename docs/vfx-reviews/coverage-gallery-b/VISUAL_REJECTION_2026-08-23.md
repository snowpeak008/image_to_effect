# Coverage Gallery B 第二轮视觉拒绝记录

日期：2026-08-23  
结论：拒绝，不得作为视觉验收证据

## 直接错误

1. `Environment` 的雾层暴露了矩形 Quad 边界，画面读成一张半透明卡片，而不是空间天气体积。
2. `Screen/UI` 只显示硬边矩形框和四个斜条，属于调试示意，不是可用的屏幕受击反馈。
3. `Aura / Area / Shield / Spawn` 复用了相同的分段圆环作为主轮廓，类型之间只剩颜色与角度差异。
4. `Impact` 在九宫格预览中的可读时间过短，用户容易只看到空格；预览调度没有照顾一次性效果的审查窗口。
5. 部分标签被大尺寸 Screen/UI 覆盖，比较场景没有守住单元格和标签安全区。

## 根因

- 把“共享 Shader、Material、基础 Mesh”错误实现成了“共享主视觉轮廓”。
- 自动测试只验证像素存在、生命周期和资源结构，没有验证硬矩形边界与类型轮廓差异。
- Screen/UI 被当成第九个世界物体来画框，而不是用 Canvas 表达真实屏幕反馈行为。

## 修复门槛

- 每个 Archetype 必须具有独立的主轮廓和主运动语义；共享资源只能作为构件。
- Environment 任意关键帧不得出现可辨认的矩形雾卡边界。
- Screen/UI 必须包含软边屏幕晕影、方向提示和中心反馈，且不得遮挡标签。
- 一次性 Impact 的预览空窗必须缩短，但 Runtime Entry 生命周期仍保持 `one_shot`。
- 新证据生成前，现有 `evidence/current-run` 只能标记为 rejected。

## 第三轮追加拒绝：Screen/UI

第三轮虽然消除了 Environment 矩形雾卡并拉开了 Aura/Area/Shield 的轮廓，但 Screen/UI 仍被用户拒绝：四个大红梯形占据右下单元格，依旧像调试遮罩，并非受击反馈。进一步审计发现正式 Prefab 把九宫格右下角锚点写死，这是预览布局污染生产资产。

修复要求：正式 Prefab 恢复全屏安全区；Gallery 只对场景实例设置缩略锚点；新增独立全屏 Screen/UI 预览；红色反馈改为低面积软边晕影、单一方向提示和小型中心命中标记。

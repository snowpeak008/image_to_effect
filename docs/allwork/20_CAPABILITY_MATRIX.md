# W-C0 能力矩阵总纲：先能力，后风格

> 执行状态（2026-08-24）：**机器开发完成，视觉签署延后。** Recipe v1 兼容的 1.2 契约、能力登记、合法性表、纯逻辑采样、事件与确定性门禁均已落地；W1 style 渲染已完成，W-C1/W-C2/W-C3 各自的“能力+皮肤”正式示范也已补齐。

> 定位：本文档确立本轮扩展的**第一原则——先补齐行为能力，再补齐元素与风格**，并定义能力在 Recipe/模板层的表达方式。21/22/23 号文档是三个能力批次的执行规格；04–09 元素批次和 10/11/17 风格批次自本文档起降级为"给能力素体上皮肤"，开发顺序见 00 号索引修订表。
> 理由：追踪弹和直线弹是**两种模板与运动协议**（不同的更新逻辑、不同的参数集、不同的验收方法）；红色火弹和蓝色冰弹只是**两份 Recipe**。前者做不出来，后者做一百个也只是换色。

## 1. 能力的定义与分类

能力（Capability）= 一个特效的**行为机制**，与元素、风格、颜色正交。分五个维度：

| 维度 | 说明 | 例 |
|---|---|---|
| **运动学** | 载体怎么动 | 直线、加速、抛物线、追踪、蛇形、回旋、弹跳 |
| **命中拓扑** | 命中怎么发生、发生几次 | 单点命中、贯穿多段、分裂二次、链式跳跃、反射 |
| **发射模式** | 一次施放产生几个载体、什么阵型 | 单发、多连发、扇形散射、环形齐射、召回齐发 |
| **时序结构** | 生效的时间形态 | 瞬发、延迟引爆、预警后爆发、周期 Tick、蓄力分级、引导可打断 |
| **空间形态** | 作用区域怎么演化 | 固定区域、扩张环、收缩聚爆、移动区域、路径残留 |

**一个完整特效 = 能力组合 + 元素皮肤 + 风格皮肤。** 例：「三连发追踪冰锥」= [多连发 + 追踪 + 单点命中] × 冰霜 × stylized。

## 2. Recipe 表达：`behavior` 块（v1.2）

在 W1 的 `style` 块之外，新增 `behavior` 块。与 style 不同，**behavior 影响模板选择与 Runtime 组件**，因此每个能力必须先有登记模板才可引用（沿用模板白名单原则）：

```json
"behavior": {
  "motion": { "type": "homing", "turn_rate": 120, "max_speed": 8, "lose_target_mode": "straight" },
  "hit": { "type": "pierce", "max_hits": 3, "damping_per_hit": 0.25 },
  "emission": { "type": "fan", "count": 5, "spread_angle": 40, "stagger": 0.05 },
  "timing": { "type": "telegraph", "warn_duration": 0.8 }
}
```

- 四个子块全部可选，缺省=该 Archetype 的最简形态（直线/单点/单发/瞬发）。
- 每个 `type` 是登记过的能力 token；未登记 token 校验报错。参数范围由能力模板 Manifest 声明。
- **能力组合合法性表**由 Manifest 声明（如 Beam 不接受 `motion.parabola`；`hit.split` 与 `hit.chain` 互斥），非法组合给可定位错误码。
- Patch 语义扩展：`set_behavior_param`（改能力参数）；`motion.type` 级别的切换不是 Patch，是换模板重建（写入文档，防止误用）。

## 3. 能力素体（Capability Blank）规范

每个能力 token 的首个交付物是**素体特效**：中性配色（白/灰蓝 `#DDE6F0`/`#8FA3B8`）、最简视觉（核心体+方向指示+命中标记三层），把全部注意力留给行为本身。

- 素体命名：`cap_<token>_<archetype>_<2d|3d>`，归档 `Recipes/Capability/`。
- 素体是正式资产，永久保留：它是该能力的回归基准、新元素套皮时的对照物、也是 Studio 里"按能力浏览"的入口。
- 素体验收后，元素批次给它套皮只需变体 Recipe（能力参数不动、style/palette/贴图引用换）——这一步不再需要行为级验收，只需视觉验收。

## 4. 能力的验收方法（机器可验优先）

能力验收与视觉验收分离，核心是**轨迹与事件的确定性采样**：

1. **轨迹采样**：Runtime 提供 `SampleTrajectory(recipe, seed, dt)` 纯逻辑接口（不渲染），输出位置/速度/事件序列 JSON。每个能力的验收 = 采样序列断言（如追踪弹：与目标距离单调递减且转向角速度 ≤ turn_rate；弹跳弹：反弹次数与衰减率匹配参数）。
2. **事件契约**：`on_launch / on_hit(n) / on_split / on_bounce / on_expire` 事件时刻与次数机器断言。
3. **确定性**：同 Recipe 同 seed 的采样序列逐字节一致（幂等原则延伸到行为层）。
4. 视觉层只验收素体三层是否正确跟随行为（方向指示朝速度方向、命中标记出现在事件点）。

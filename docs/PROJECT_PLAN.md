# VFX Composer 项目计划

> 文档状态：v1.0 实施基线；内部 MVP 0.1.0 已验收  
> 项目阶段：M8 已通过（2026-08-22）；未进行外部发布  
> 当前交付：Unity 2D/3D 火球内部 MVP；后续技能扩展按 P2/变更控制执行  
> 基线勘定：Unity 版本已定版 **2022.3.62f3c1 + URP 14.x**（见 [决策定版](DECISIONS.md)）  
> 关联文档：[设计路线](DESIGN_PLAN.md) · [技术开发计划](DEVELOPMENT_PLAN.md) · [执行计划](EXECUTION_PLAN.md)

## 1. 项目章程

### 1.1 项目愿景

开发一套 Unity 特效生产工具，使用户能够通过自然语言描述技能表现，由 Codex 规划为结构化 Recipe，再由 Unity 中的确定性编译器使用本地模板生成可编辑、可复用、可验证的 2D/3D 特效资产。

### 1.2 MVP 价值

MVP 需要证明：

- 文字需求能够被转换为严格结构。
- AI 不必直接修改 Unity 资产。
- 模板可以被稳定组合和参数化。
- 生成结果可以局部修改和重复构建。
- 2D 与 3D 可以共享阶段和模块语义。

### 1.3 成功标准

项目成功不是“第一版火球足够华丽”，而是：

1. 编译链稳定。
2. 输入与输出可追溯。
3. 非法输入不会损坏项目。
4. 重复构建可复现。
5. 局部需求产生局部修改。
6. 生成物可在 Unity 游戏运行时独立播放。

## 2. 项目范围

### 2.1 In Scope

- Unity 2022.3.62f3c1 + URP 14.x。
- Unity 自定义 UPM Package。
- 2D 火球完整闭环。
- 3D 火球扩展。
- JSON Recipe 与 Schema。
- 模板 Manifest 和 Catalog。
- Validator、Dry Run、Compiler。
- Runtime 阶段控制器。
- 固定预览场景。
- 基础预算检查。
- Patch 和局部重建。
- Codex 文件工作流。
- 自动化测试和使用文档。

### 2.2 Out of Scope

- Cocos 和 Unreal。
- 云端素材生成。
- VFX Graph 任意图生成。
- 运行时 AI。
- 游戏玩法、伤害和网络逻辑。
- 自动视觉 Critic。
- 商店发布、在线账号、计费与多人协作后台。
- 全技能类型覆盖。

### 2.3 已固定方向

- 当前只做 Unity，不建立 Cocos/Unreal 代码或虚拟适配层。
- 先完成 2D 火球闭环，再开发 3D 火球。
- 第一版使用 Built-in Particle System，不以 VFX Graph 为核心。
- 第一版只使用本地、人工审核过的模板。
- JSON Recipe 是生成来源，生成资产默认处于 Managed 状态。
- 先完成文件和 Unity Editor 工作流，再评估 CLI 与 MCP。
- AI不直接编辑 Unity 序列化资产。

## 9. 阶段门禁

### Gate A：允许制作模板

前置条件：

- Recipe 和 Manifest 字段通过评审。
- 模板 ID 与参数命名规则确定。
- Generated/Templates 路径确定。

### Gate B：允许开发编译器

前置条件：

- 至少一个主体、拖尾和命中模板可用。
- 参数 Binding 有明确实现。
- 非法输入样例完成。

### Gate C：允许接入 Codex

前置条件：

- 手写 Recipe 构建稳定。
- 验证错误结构化。
- 编译器幂等。
- 模板目录无法被写入。

### Gate D：允许开发 3D

前置条件：

- 2D 完整闭环通过。
- Patch 与局部构建通过。
- Recipe v1 无重大字段缺陷。

### Gate E：允许发布 MVP

前置条件：

- P0 项完成。
- 所有验收样例通过。
- 无阻断级缺陷。
- 安装、使用、回滚文档完成。

## 10. 验收场景

### A1：默认 2D 火球

输入标准 Recipe，生成完整 Prefab并播放。

### A2：重复构建

连续构建相同 Recipe，不生成重复资产，不产生无意义修改。

### A3：非法模板

使用不存在的 `templateId`，构建被拒绝且不改变 Generated 目录。

### A4：参数越界

火星 rate 超过模板上限，按项目策略报错或显式截断并记录。

### A5：模板保护

任何构建和 Patch 都不能修改 Templates 目录。

### A6：局部 Patch

执行“火星减少一半”，只有 `embers` 模块和相关构建记录变化。

### A7：运行时独立

断开 Codex并关闭 Editor工具后，生成 Prefab仍可在 PlayMode和构建版本中播放。

### A8：3D 扩展

使用相同 Launch/Travel/Impact 语义生成 3D 火球，Unsupported 能力必须显式报告。

| 指标 | MVP 目标 |
|---|---|
| P0 自动化测试通过率 | 100% |
| 相同 Recipe 构建一致性 | 100% |
| 非法模板拦截率 | 100% |
| 模板目录误写 | 0 |

## 12. 风险登记

| 风险 | 概率 | 影响 | 应对措施 | 触发信号 |
|---|---|---|---|---|
| Recipe 设计过度抽象 | 中 | 高 | 只围绕火球实际需求建模 | 大量字段没有首个案例使用 |
| Recipe 过度绑定 Unity | 中 | 中 | 保留语义 kind，Binding放 Manifest | Recipe 出现大量 Unity 类名 |
| 模板质量不足 | 高 | 中 | 先验收模板再开发编译器 | 编译错误与美术问题无法区分 |
| 直接修改生成物导致覆盖 | 高 | 中 | Managed 标识、警告、后续 Detach | 用户反馈重建丢失调整 |
| Unity 序列化变化 | 中 | 高 | 只使用官方 Editor API，锁定版本 | 升级后 Prefab测试失败 |
| 参数 Binding 失控 | 中 | 高 | 使用白名单 Binding Handler | Manifest开始记录任意属性路径 |
| 重建留下孤立资产 | 中 | 高 | 临时构建、原子替换、回滚测试 | Generated目录持续膨胀 |
| Codex产生非法Recipe | 高 | 低 | Schema与语义验证作为硬门禁 | 首次生成频繁失败 |
| 静态预算被误认为真机性能 | 中 | 高 | 报告明确标注预检 | 项目以粒子数代替真机测试 |
| 2D设计无法扩展3D | 中 | 中 | 3D作为独立里程碑验证 | Recipe含大量2D专用字段 |
| 范围持续扩大 | 高 | 高 | 变更控制与P0/P1/P2分级 | MVP加入云端、MCP或更多技能 |

## 13. 变更控制

任何新增需求先记录为变更项，并回答：

1. 是否是当前 MVP 验收所必需？
2. 是否改变 Recipe v1？
3. 是否增加新模板类型？
4. 是否影响既有生成物兼容性？
5. 是否增加新的外部依赖？
6. 延期或删除哪个现有工作项？

默认规则：

- 不影响 MVP 的需求进入 P2。
- Recipe 破坏性变更必须增加版本和迁移器。
- Unity 大版本升级视为独立变更，不在功能迭代中顺便进行。

## 14. 缺陷等级

### Blocker

- 项目无法打开或编译。
- 模板被修改或删除。
- 构建破坏现有成功资产。
- 运行时无法播放生成物。

### Critical

- 相同 Recipe 得到不一致结构。
- 非法模板未被拦截。
- Patch 修改错误模块。
- Runtime 引用了 Editor 程序集。

### Major

- 错误信息不清楚。
- 预览和运行时表现明显不一致。
- 预算报告缺少关键数据。

### Minor

- UI、日志、命名或文档问题。

MVP 发布要求 Blocker 和 Critical 为零。

## 15. Definition of Ready

一个开发项进入实施前应具备：

- 明确目的。
- 输入和输出。
- 依赖项。
- 验收方法。
- 失败行为。
- 是否修改 Recipe 或 Manifest。
- 是否影响现有生成资产。

## 16. Definition of Done

一个开发项完成时必须：

- 功能实现。
- 测试覆盖成功与失败路径。
- 文档更新。
- 示例更新。
- 无新增 Blocker/Critical。
- 通过相关阶段门禁。
- 构建结果可追溯。

## 17. 评审节奏

建议以里程碑为单位评审：

1. M1：评审数据模型，不评审画面。
2. M2：评审模板和参数契约。
3. M3：评审构建稳定性。
4. M5：评审局部修改闭环。
5. M6：评审文字输入的可靠性。
6. M7：评审 2D/3D 抽象是否成立。
7. M8：最终验收。

每次评审记录：

- 通过项。
- 阻断项。
- 新风险。
- 决策与理由。
- 下一阶段是否 Go/No-Go。

## 18. 版本策略

### Recipe

- `recipeVersion`：结构版本。
- 破坏性字段变化增加主版本。
- 已生成样例必须有迁移测试。

### Template

- 每个模板有独立 `templateVersion`。
- 参数删除或语义改变属于破坏性变更。
- 视觉调整但参数契约不变可增加小版本。

### Package

- MVP 前使用 `0.x`。
- 内部首个可用版本建议 `0.1.0`。
- 2D 闭环可标记 `0.2.0`。
- 3D 验证和稳定化后再考虑 `1.0.0`。

## 19. 项目停止或转向条件

满足任一情况时应暂停扩展并重新评审：

- Unity API无法可靠生成或更新目标 Prefab。
- Recipe 为支持一个火球就需要大量引擎内部细节。
- 模板参数无法稳定映射。
- 重建无法避免破坏用户资产。
- 维护成本明显高于手工复制模板。
- 2D 闭环没有完成却持续加入新引擎或云端能力。

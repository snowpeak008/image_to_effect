# ADR-010：内容范式——通用美术特效生产线的原型/元素/风格模型与技术族闭集

状态：`ACCEPTED`（2026-09-05，用户直接裁定，主 agent 记录；后续 T2 产出的原型目录与 Recipe v2 schema 以修订版形式并入）
日期：2026-09-05
规范令牌：`CONTENT_PARADIGM_V1`

本 ADR 是**路线宪法**：它推翻此前全部 Unity 内容层的问题定义，重新回答"这个系统生产的是什么"。治理与交付外壳（Recipe 契约机制、受限构建与三件套写入面、fail-closed 门禁、CLI/MCP/Desktop 三入口、队列、AI 生成/精修回路、草稿版本链）**不在推翻范围内**，它们与内容范式无关。

## 0. 起因（用户裁定原文摘要，2026-09-05）

九宫格与 T1 拟真火球复验结论：现有产物"像一个小孩随便贴了几张图——简单、粗糙、没有设计感、没有美感、无法惊艳、无法做特殊需求"。根因判定：系统对特效制作范式缺乏认知层，内容模型 = 单一 billboard sprite 粒子范式（Illusion 档）× 参数填空，T1b 已触其天花板。过去全部内容产物（含 sprite 模板、九宫格、Spine 类动画）定性为"能看但达不到商业化水平的自嗨型产物"，**全部清理**。

## 1. 产品定位

**通用美术特效生产线**。不服务任何特定游戏或游戏类型。覆盖目标：尽可能多的 2D 与 3D 特效类型，上限由 Unity 引擎自身能力决定，**只依赖 Unity**，不接外部特效工具与外部管线。

## 2. 三条独立的轴

| 轴 | 定义 | 与其他轴的关系 |
|---|---|---|
| **内容 = 原型 × 元素** | 原型 = 与外观无关的结构（层结构、节拍、对外接口）；元素 = 物理属性（火/冰/雷/水/风/土/毒/光/暗/奥术/科技/血…，决定运动倾向与形态倾向） | 元素属于内容轴：水球与火球在结构上同为"投射物"，但形态差异大，不能只靠风格滤镜表达 |
| **风格** | 渲染取向：卡通、像素、写实、风格化、水墨、霓虹、全息、暗黑… | **完全独立**于内容——任何内容都可套任何风格。首批：**卡通、像素**。像素风走 shader 量化/色阶分级（自包含），不走低分辨率 RenderTexture（触碰资产外） |
| **维度** | 2D / 3D | 同一原型/元素/风格的两种投影：3D 用体积噪声、真实网格、3D 局部光；2D 用平面 UV 流动、quad/Sprite 网格、排序层、2D 局部光。不是两套系统 |

覆盖面由三轴组合爆炸提供：维护 N 原型 + M 元素 + K 风格个正交单元，获得 N×M×K 种完整特效。**任何以单一具体特效为交付目标的任务卡即为偏离**（见 §7）。

## 3. 原型目录

原型由系统性穷举 Unity 可表达的特效空间产生，不由业务需求圈定，持续扩充。**v1 = 58 个原型 + 编排级组合规则**（T2a 交付，见 `docs/design/paradigm/PROTOTYPE_CATALOG_v1.md`；穷举法 = 空间形态 6 × 时间形态 5 × 附着主体 5 = 150 格剔除不可表达/仅参数差异/资产外格，并要求"层结构·节拍·接口至少一项有实质差异"）。初版分类骨架（下方 34 个点名项已全部落到原型，穷举另补 16 个）：

战斗动作（投射物、光束、斩击、冲击、范围、召唤、位移轨迹、连锁）｜状态持续（光环、Debuff、护盾、蓄力、挂点）｜反馈事件（受击、暴击、治疗、获得、消散、登场）｜物理破坏（破碎、崩塌、残骸、布料、液体飞溅）｜环境氛围（天气粒子、雾烟云、水面熔岩、传送门、过渡）｜UI 内特效（按钮、奖励、抽卡、合成、HUD 提示——**仅指 UGUI 内的特效材质与粒子，不改 UI 本身**）｜编排级（多原型时间线组合）。

每个原型一页规格：职责、层结构（每层职责 + 可选技术族）、节拍、2D/3D 投影差异、对外接口（特有参数）、六档性能降级策略。**用户只审分类与数量，细节放权。**

## 4. 技术族闭集（特效资产内部）

特效产物 = **一个完全自包含的预制体**，丢进任何场景即可播放，对外部零假设。资产内部可用技术族 **5 个**，全部 Unity 原生：

1. **程序化材质**（Shader Graph）——形态被算出来：多层噪声、SDF、阈值消散、顶点位移、菲涅尔、流动 UV、色阶量化（像素/卡通）。这是替代序列帧的核心。
2. **GPU 粒子**（VFX Graph）——高密度与规则驱动运动：湍流/向量场、吸引排斥、SDF 碰撞、事件分裂、网格粒子。
3. **CPU 粒子**（ParticleSystem）——2D 排序敏感场景、轻量碎屑、低端档位降级目标。
4. **网格几何**——基础几何（球/quad/cube/环/锥/螺旋）与程序化生成网格；顶点位移变形；预破碎 + Rigidbody；Cloth；Trail/Line 网格。
5. **局部光**——预制体子节点上的点光/聚光（2D 用 2D Light），随节拍变化。它是特效自身的一部分。

**特效资产外部，一律不做、不碰**：后处理 Volume、相机（震屏/FOV/慢动作）、UI 布局、场景全局光、时间缩放。它们属于用户的游戏工程。预制体只开放接口（§6）。

## 4bis. T2a 后的用户裁定勘注（2026-09-05）

| # | 议题 | 裁定 |
|---|---|---|
| 1 | **折射 / 屏幕扭曲层** | 采用**可选层 + 自动降级**：运行时检测 URP `Opaque Texture`，开启则走 Scene Color 真折射，未开启自动退回法线扰动，两条路均不报错。理由：真折射对用户的全部要求仅为勾一个官方复选框；自带 Renderer Feature 方案（需用户手动添加 Feature、额外全屏拷贝、跨版本 API 脆弱、与用户既有 Feature 冲突）被此方案完全支配 |
| 2 | **UGUI Overlay 画布下的粒子** | 双方案：Screen Space-Camera / World Space 画布用真粒子；Overlay 画布自动降级为材质内程序化伪粒子（shader 多实例 SDF 点） |
| 3 | **编排引用语义** | **内联**（编译时展开合并，产出单一自包含预制体）。链接方案在 schema 中保留字段但 v1 不实现，后续按需再议 |
| 4 | **像素风 3D** | 接受"体素感"（栅格随物体空间），2D 为像素风主场 |
| 5 | **低端档卡通描边** | 手机低/中档取消真描边壳，改材质暗边 |

## 5. 素材纪律

- 形态**一律程序化**（噪声/SDF/顶点位移/程序化网格）。**绝对禁止序列帧特效**。
- 几何一律 Unity 基础几何或脚本程序化生成。
- 外部出图（本地 Codex CLI）**仅作辅助**：渐变查找表（色板）、遮罩形状、噪声种子。不承担任何画面主体。
- 局部光是原型作曲的一等成员，不是可选装饰。

## 6. 对外接口（尽量全开）

每个预制体暴露：**标准生命周期事件**（Launch/Travel/Impact/End 等按原型定义）、**标准参数**（色板、强度、缩放、播放速度）、**原型特有参数**（护盾破裂进度、光束长度、破碎块数…）。全部可在 Inspector 与代码中调节。用户在此之上自行接震屏、后处理、音效。

## 7. 性能档位

六档可主动选择：手机低/中/高、PC 低/中/高。每个原型的每一层声明降级策略（如 GPU 粒子 → CPU 粒子、噪声层数递减、局部光关闭）。档位是构建期输入，不同档位产出不同预制体。

## 8. 验收面

- **Unity 内九宫格画廊场景**：2D 与 3D **两个独立场景**（正交/透视相机、排序层/光照环境各异），可左右翻页，切到目标场景点 Play 即开始检查。它是 T2 必交产物，也是以后每批内容的标准验收面。
- **范式验收**：用户只对"原型 × 元素 × 风格各选 3 个交叉出的 9 格"做一次判定，通过即认可范式成立；后续批次走审计、用户抽检。

## 9. 旧资产处置：全部清理

现有 Unity 内容层——sprite 模板库（6 模板）、全部 recipe 资产、全部 Generated 产物、预览场景、构建清单、以及仅服务这些资产的 Editor 代码（S/W/cohort 系列作者与证据链）与测试——**全部清理**，不归档为 legacy。ADR-009 的谓词族随旧 kind 闭集一并退役，其"按族的机器可查视觉谓词 + fail-closed + 显式豁免"的**方法论**由新范式的门禁继承。

**清理顺序纪律**：先立新骨架（Recipe v2 schema、新目录、新门禁、画廊），再删旧内容，删除与替代在同一批审计内闭合，任何时刻 EditMode/.NET 全量不得处于"无替代物的红"。.NET 侧 `AI.Providers` 的目录快照、预置骨架、精修知识、prompt 片段随新目录 re-export，其契约机制不变。

## 10. 防偏离机制（硬约束，审计第一项）

1. **例子不进正文**：具体特效名只能出现在任务卡的"验证样片清单"一节，且样片清单必须跨 ≥3 原型 × ≥3 元素。
2. **覆盖面声明**：每张任务卡开头必须写明完成后三轴各覆盖到哪里；无声明不派发。
3. **本 ADR 为路线宪法**：`DEV_MEMORY.md` 顶部固定指向本文件，每次会话恢复先读。任何以单一特效为目标、或把资产外事项纳入特效、或引入序列帧的任务，审计直接 FAIL。

## 11. 落地卡序（详见主计划 §8）

T2a 原型目录 v1 + Recipe v2 schema 草案（docs，用户审分类与数量）→ T2b 技术族实现规格 + 首批风格（卡通/像素）的材质族设计 + 画廊场景 → T2c 范式样片（3 原型 × 3 元素 × 1 风格，2D/3D 各一组）+ 旧资产清理（同批闭合）→ 用户 9 格判定 → T3 技术族逐族落地 → T4 原型/元素/风格批量铺开 → AI 回路改造（prompt 从模板表变为作曲规则 + 三轴目录）。
